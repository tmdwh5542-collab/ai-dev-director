# 사무실·동시 접속 최적화

2026-11-15 소스 패치. UI가 쓰는 상태만 읽고 변화가 있을 때 보고함을 갱신하도록 변경했습니다. AI 추론 횟수·모델·업무 권한을 바꾸는 패치가 아닙니다. 새 설치 ZIP은 사용자 요청 전까지 생성하지 않습니다.

## 같은 격리 환경에서 측정한 결과

Linux의 실제 로컬 HTTP 서버에 시연용 미션 163개, AI 사용 기록 6,656개를 넣었습니다. 준비 요청 뒤 15회 순차 요청의 중앙값과 4개 클라이언트/16회 요청의 중앙값을 측정했습니다. 실제 AI·API·계정 로그인은 호출하지 않았습니다.

| 항목 | 변경 전 | 변경 후 |
|---|---:|---:|
| 사무실 응답 중앙값 | 104.55ms | 11.54ms |
| 순차 요청 p95 근사값 | 130.23ms | 12.44ms |
| 4개 클라이언트 동시 요청 중앙값 | 2,006.42ms | 70.44ms |
| 변경 없는 팀·회사 정보를 제외한 응답 | 7,618바이트 | 2,596바이트 |
| 최초 응답 | 11,476바이트 | 6,454바이트 |

순차 p95는 15개 샘플 중 두 번째로 큰 값을 사용합니다. PC 사양·보관량·디스크·네트워크에 따라 실사용 결과는 달라집니다. 이 수치는 서버 응답 처리 시간이며 AI가 코드를 생성하는 시간이나 인터넷 지연을 뜻하지 않습니다.

완료 회의 200개와 과거 대표 보고 100개에 큰 문맥·증거 본문을 추가한 별도 시험에서는, 간소 조회 적용 후에도 남아 있던 반복 문서 읽기의 중앙값 110.53ms가 읽기용 투영 캐시 적용 후 12.71ms로 줄었습니다. 이 시험의 비교 기준은 이미 간소 조회를 적용한 상태이며 위 표의 변경 전과 다릅니다.

재현 명령:

```sh
.venv/bin/python scripts/benchmark_office.py
.venv/bin/python scripts/benchmark_office.py --large-journals
```

두 명령 모두 임시 DB·프로젝트·서버를 만들고 종료 후 삭제합니다. 운영 데이터에 쓰지 않습니다. 숫자는 반복 실행 시 변동할 수 있습니다.

## 변경 내용

- 사무실 전용 조회는 전체 상세 모니터, 연구 상태, 적용 대기 결과를 매번 생성하지 않습니다. 최신 실제 실행 상태·프로젝트·승인 정보는 같은 DB와 승인 판정 함수를 사용합니다.
- 오늘의 호출·시간·토큰 합계는 SQLite에서 집계합니다. 전체 사용 이력과 미션별 사용 이력을 Python으로 전부 불러오지 않습니다. 기존 상세 사용량 경로는 유지합니다.
- 화면이 보여주는 최근 호출 5건만 보내고, 사무실에는 불필요한 이벤트·전체 통계·단계별 상세 실행 조회를 제외했습니다.
- 회의/대표 보고는 작은 읽기 모델을 최대 8개 파일 경로에 한정해 캐시합니다. 파일 교체 또는 수정 메타데이터가 바뀌면 새로 읽습니다. 캐시 반환값은 별도 복사본이며 수정 요청에 공유하지 않습니다.
- 진행 중인 AI 회의는 캐시 적중 시에도 소유 프로세스 생존을 검사합니다. 프로세스가 종료되면 기존 중단 판정을 다시 수행하며, 살아 있는 것처럼 캐시하지 않습니다.
- 임원회의는 현재 발표와 과거 회의 수만 반복 조회하고, 과거 전체 증거를 폴링으로 전송하지 않습니다. 원본 기록은 삭제하지 않습니다.
- 보고함과 대표 보고의 조회는 revision이 같으면 작은 `unchanged` 응답을 사용합니다. 기존 상세/전체 API와 승인 충돌 판정은 유지합니다.
- 보고함의 별도 주기적 네트워크 조회를 사무실 상태 갱신에 통합했습니다. 변경이 없는 안건 DOM을 재생성하지 않아 체크 상태·노드·입력 중인 대표 답변을 유지합니다.
- 연결 실패 시 자동 재시도는 약 3→6→12→24→30초로 늦춥니다. 수동 새로고침과 화면 복귀는 즉시 재접속을 시도합니다. 숨긴 탭은 사무실과 보고함의 주기적 조회를 멈춥니다.

원래의 대기 중 약 8초/작업 중 약 3초 갱신 주기는 유지하며, 회의 대기·실행 상태도 작업 갱신 조건에 포함했습니다. AI 응답·작업 결과·안전 승인 자체를 캐시하지 않습니다.

## 검증

`tests/test_office_performance.py`는 SQL 합계 동등성, 실제 실행/승인 상태 선택, 불필요한 상세 조회 방지, 캐시 수정·교체·삭제 감지, 캐시 크기 제한, 원본 보존, 프로세스 사망 감지, 이전 API·인증 경계를 검증합니다.

`tests/browser/office_performance.cjs`는 초기 오류의 재시도 간격과 수동 복구, 반복 갱신 시 안건 DOM/체크 상태 및 대표 답변 유지, 변경 없는 보고함의 추가 요청 억제, 새 기록 반영, 숨긴 탭 통신 중지·복귀를 실제 브라우저에서 검증합니다. 기존 사무실·회사 구성 시나리오도 사용합니다.

최종 검수: 전체 회귀 **773 passed, 2 deselected** (344.23초). 새 성능·정합성 검사 7건, 성능 브라우저 시나리오, 기존 사무실/회사 시나리오, 실제 HTTPS PC·휴대폰·태블릿 연동과 실제 QtWebEngine 검수가 통과했습니다. 구문 및 변경 공백 검사도 통과했습니다.
