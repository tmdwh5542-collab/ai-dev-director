# 게임 엔진 대응판 재검수 기록

검수 기준일: 2026-11-13 (한국 시간).
Fix1 설치판을 기준으로 설치·전용 앱·작업실·개발 실행·결과 반영을 다시 확인했습니다.
Windows 사용자 PC의 깜박임 현상과 Windows EXE 실행 자체는 이 Linux 환경에서 직접 재현하지 못했습니다.

## 확인하고 수정한 내용

- 기존 작업실 화면 갱신/중복 타이머 수정을 유지하고, 새 대화·프로젝트 선택 후 프레임 문서와 입력 초점·펼친 상세 내용이 유지됨을 재확인했습니다.
- Godot/Unity 주요 코드·씬·리소스·UID/메타데이터와 오디오·모델 파일을 새 파일 스냅샷에 포함하도록 확장했습니다.
  게임의 `token_pickup.gd` 같은 이름을 자격증명으로 오인해 제외하지 않도록 수정하고, 실제 민감 설정 이름의 제외는 유지했습니다.
- 새 지원 파일이 크기 상한을 넘으면 조용히 누락하는 대신 오류를 반환합니다. 1개 16MiB, 합계 128MiB입니다.
- 프로젝트 문맥 탐색에서 Godot/Unity를 식별하고 엔진 캐시를 제외합니다.
- 게임 개발 방식에 엔진 버전·작은 플레이 루프·프레임 속도 독립성·씬/에셋 연결·실제 테스트·미검증 범위 구분을 추가했습니다.
- 전용 앱 메뉴에 게임 프로젝트 검증 설정을 추가했습니다. 프로젝트별 설정은 감독관의 `data/engine-projects.json`에 저장됩니다.
- 실제 Godot 가져오기/테스트와 Unity의 새 NUnit 결과 파일을 처리하는 검증 어댑터를 추가했습니다.
  누락/빈 결과/전부 스킵/손상 보고서/엔진 오류를 통과로 바꾸지 않습니다.
- 네이티브 파일 도구 훅에서도 허용 경로와 보호 경로를 직접 검사하도록 강화했습니다.
  작업 폴더 안이라는 이유만으로 미허용 경로를 허용하지 않으며, 쓰기 허용이 없는 요청도 거부합니다.
- Windows 경로를 다른 OS에서 검사할 때 AI CLI 식별과 절대 경로 구분을 보완했습니다.
- Windows 백그라운드 Git·CLI·폴더 선택 프로세스는 새 명령창을 만들지 않도록 했습니다.

## 실제로 실행한 검증

- 별도의 빈 Python 가상환경에서 배포 요구 패키지 설치.
- ZIP 추출과 파일별 해시 확인 → 한글·공백 경로 설치 → 실제 companion 서버 시작 → 미션 센터/게임 방식 응답 → 재실행 시 서버 재사용.
- 재설치 복사 후 설정, 기록, 게임 엔진 설정 보존.
- 실제 PySide6/QtWebEngine: 미션 센터, 보고서 저장, 취소된 탐색 뒤 화면 유지, 작업실 진입, 새 대화, 프로젝트 선택.
- 실제 Qt 게임 설정 대화상자의 입력/저장과 프로젝트별 검증 설정 적용.
- Linux용으로 GUI 셸을 PyInstaller로 실제 빌드하고, 한글·공백 설치 경로의 백엔드를 시작해 내부 페이지 로딩과 UI 스크립트 동작 확인.
- 브라우저 회귀 시나리오 3개: 미션 센터, 실행 센터, 작업실 안정성.
- 실제 Godot 4.6.3: SVG 가져오기와 씬 연결, 이동과 프레임 속도 독립성, 실패 동작 검출.
- 실제 Git/엔진 파이프라인: 초기 4개 테스트 → 격리 폴더에서 체력 경계 동작 추가 → 5개 테스트 → 원본 반영 → 원본에서 5개 재검증.
  HEAD/BUILDER/REVIEWER 응답은 이 검증에서 테스트 대역을 사용했고, Git·엔진·검증·반영은 실제로 실행했습니다.

## 회귀 테스트 해석

수정 전 전체 검사에서는 665 passed, 14 failed, 1 error였습니다.
기존 실패를 그대로 무시하지 않고 실제 제품 결함과 오래된 테스트 기대값을 나눠 확인했습니다.

- 실제 수정: 외국 형식의 절대 경로와 네이티브 훅의 쓰기 범위 검사, Windows CLI 이름 식별, 게임 파일 보존.
- 테스트 정정: Linux의 죽은 좀비 프로세스를 실행 중인 누수로 간주하던 검사, Windows 드라이브 형식만 가정한 절대 경로 검사,
  `os.name`을 전역으로 바꿔 pathlib까지 깨뜨리던 모의 설정, 강화된 훅이 거부해야 할 쓰기를 허용하라고 기대하던 검사.
- 보호 경로 검사는 유지했습니다. 읽기 전용 요청에서 모호한 범위 사유만 제거하고 보호 경로 사유는 계속 확인합니다.
- 게임 레벨 JSON은 소스 데이터로 보존하며 secrets/credentials 및 민감 설정 이름은 제외하는 기대값으로 맞췄습니다.

별도 깨끗한 설치 환경의 패키지/서버/재설치 보존 점검도 통과했습니다.

## 검증하지 못한 범위

Windows EXE 빌드와 COM 바로가기의 실제 실행, 사용자 PC의 그래픽 드라이버 환경,
실제 Unity 실행/라이선스, 실제 로그인된 AI CLI의 추론 결과는 이번 자동 검증에 포함하지 않았습니다.
Unity는 NUnit 보고서 처리 경계를 확인했습니다. 모든 게임 엔진·사용자 에셋 형식·플랫폼 내보내기를 보장하지 않습니다.
게임의 실제 조작감·시각/소리·성능·최종 내보내기는 에디터와 대상 기기에서 추가 확인해야 합니다.

사용 방법은 [게임 제작 안내](GAME_DEVELOPMENT_KO.md)를 참고하세요.
