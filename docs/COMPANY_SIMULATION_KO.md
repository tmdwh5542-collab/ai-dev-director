# 캐릭터 회사 · 부서 · 회의 운영

최신판은 픽셀 사무실과 2D 초상화 10종을 사용합니다. [새 UI와 스타일 선택](PIXEL_STUDIO_KO.md)을 참고하세요.

처음 회사 사무실을 열면 대표 캐릭터를 생성합니다. 이름(최대 24자), 남성/여성, 나이(18~100세), 의상 색상을 고르고 배경을 선택하세요. 새 설치는 대표 한 명으로 시작합니다. 이전 버전에서 저장한 팀이 있으면 그대로 유지합니다.

회사는 이 PC의 여러 프로젝트에 공통으로 적용됩니다. 프로젝트별로 캐릭터를 다시 만들지는 않습니다. **대표·사무실 설정**에서 언제든 변경할 수 있습니다. 성별과 나이는 외형·프로필 표현용이며 능력·권한·업무 배정에 영향을 주지 않습니다.

## 직접 채용하는 조직

미리 마련된 부서는 기획과, 디자인과, 개발과, 레벨과, 테스트과, 품질검수과, 경영지원과입니다. 부서 자체는 비어 있고, 직원은 사용자가 생성해야 생깁니다.

- **직원 채용·편집 → 직원 직접 만들기**에서 이름·성별·나이·의상·부서·직급·전문 분야·담당 직무를 설정합니다.
- 부서당 **과장을 포함해 최대 4명**, 전체 28명입니다. 대표와 프로그램의 테스트 서버는 별도입니다.
- 부서당 과장은 1명입니다. 실제 개발을 시작하려면 직원이 있는 각 부서에 과장이 있어야 하고, 전체 팀에 기획·구현·독립 검수 담당이 각각 필요합니다.
- 채용 중에는 빈 팀과 미완성 부서를 저장할 수 있습니다. 준비가 안 된 팀으로 실행 요청하면 필요한 채용을 안내합니다.
- 경영지원과에서 **비서** 직급을 선택할 수 있습니다. 비서도 부서 정원 4명에 포함됩니다.
- **게임 개발팀 6명 불러오기**는 편의를 위한 초안입니다. 저장해야 적용됩니다. 기존 이름과 직무를 바꾸므로 필요할 때만 사용하세요.

기획과 과장이 기획 담당이면 우선 총괄합니다. 구현은 전문 분야와 명시된 직원 배정을 우선합니다. 같은 부서·전문 분야의 직원이 여러 명이고 명시 배정이 없으면 해당 미션에서 배정 횟수가 적은 직원에게 다음 단계를 줍니다. 독립 검수도 명시 배정이 없으면 검수 직원 사이에서 배정 횟수를 고려합니다.

직원은 기존 3개 AI 연결을 공유합니다. 과장·비서·팀원이 별도 유료 계정이나 동시에 코드를 쓰는 프로세스로 생기지는 않습니다. 한 미션의 단계들을 나눠 순서대로 수행하며, 진행 중인 미션은 시작할 때 캡처한 팀과 이름·직무를 유지합니다. 새 팀은 새 미션부터 적용됩니다.

## 사무실과 이동

배경은 **대기업 본사 / 자유로운 스튜디오 / 그린 오피스**입니다. 사무실 색감과 가구·창밖 장식이 바뀌는 입체 일러스트 화면입니다. 실사 3D 엔진이나 특정 기업의 실제 사무실을 재현한 화면은 아닙니다.

- 빈 바닥을 누르면 대표가 해당 위치로 걸어갑니다.
- 직원은 대기 중 사무실을 이동하고, 실제 AI 호출이 시작되면 책상 또는 회의 위치로 이동합니다.
- 작업·회의·사용자 확인·연결 확인 말풍선은 수신한 실제 상태에 연결합니다. 이동 자체는 시각적 표현이며 진행률이나 작업 완료의 증거가 아닙니다.
- 캐릭터·책상·직원 이름을 누르면 프로필과 현재 업무를 표시합니다. 회사 화면의 클릭만으로 해당 직원과 별도의 AI 채팅이 시작되지는 않습니다.
- 큰 조직은 전체 보기에서 대표와 부서 과장을, 부서 선택 시 해당 부서 직원 최대 4명을 표시합니다. 아래 직원 목록으로 바로 선택할 수도 있습니다. 부서 버튼에 실제 업무 중 직원 수를 표시합니다.
- 운영체제의 동작 줄이기 설정에서는 이동 애니메이션을 생략합니다. 연결이 끊기거나 화면이 숨겨지면 이동 처리를 멈춥니다.

## 실제 회의와 비서 보고함

프로젝트를 선택한 뒤 **회의 · 비서 보고함**에서 부서·주제를 정하고 **회의 시작**을 누릅니다.

1. 부서 직원들이 담당 직무·프로젝트 파일 목록·최근 미션 결과·앞선 의견을 참고해 의견과 반대 근거를 냅니다.
2. 과장이 안건을 최대 6개로 종합합니다.
3. 논의 담당과 다른 AI 연결의 검수 직원이 안건별로 독립 검토합니다. 검수 부서는 기획 담당을 논의에 초청하고 검수 담당은 독립 검토합니다.
4. 검토가 완료되면 실제 발언·분류·근거·결과를 보고서로 보존합니다. 중간 호출 실패나 응답 형식 오류가 있으면 완료나 합의를 꾸며내지 않고 실패로 남깁니다.

**부서 채택**은 현재 목표 범위 안의 구현 세부사항·테스트 보강·문서 제안 중, 영향 표시가 없고 독립 검토자가 중요하지 않다고 확인하며 동의한 경우에만 가능합니다. 구조·범위·비용·설치·외부 의존성·배포·데이터 변경이나 불확실한 안건은 대표 승인 대기합니다. 반대/보류 이유도 남깁니다.

회사의 **미션 완료 후 부서 개선회의 자동 진행**을 켜면 완료된 미션마다 한 번 후속 부서회의를 접수합니다. 중요 승인 대기 안건이 3개 이상 모이면 최대 6건을 한 임원회의에 올립니다. 임원회의는 같은 안건 ID에 추가 검토를 붙이며 중복 안건이나 자동 승인을 만들지 않습니다. 이미 임원 검토한 안건을 계속 자동 재검토하지 않습니다. 회의가 진행 중이거나 호출 연결이 없으면 보류/실패 사유를 기록하고 무제한 재시도하지 않습니다.

회의당 최대 9회 AI 호출, 호출당 최대 180초이며 기존 로그인된 CLI 구독·사용량을 사용합니다. 자동 후속 임원회의는 별도 한 회의입니다. 전체 회의는 한 번에 하나만 진행합니다. 개발 호출과 회의 호출은 같은 연결의 사용량을 소비할 수 있습니다. 자동 회의를 끄고 수동 회의만 열 수도 있습니다.

비서를 생성했다면 비서 이름으로 보고함 전달을 표시합니다. 보고서 취합은 프로그램이 수행한다고 명시하며, 실제로 하지 않은 비서 AI 호출을 꾸며내지 않습니다. 비서가 없어도 대표 보고함에서 확인할 수 있습니다.

## 중요한 안건을 모아서 승인

현재 프로젝트의 안건에서 내용을 확인하고 체크한 뒤 **선택 안건 일괄 승인 / 반려**를 누릅니다. 한 번에 최대 30건입니다. 다른 창이 먼저 처리했으면 덮어쓰지 않고 새로고침을 안내합니다.

채택·승인된 제안은 **같은 프로젝트의 이후 계획에 참고 지침으로 전달**합니다. 승인 버튼 자체가 프로그램 설치, 결제, 코드 적용, 배포를 실행하지 않습니다. 실제 개발은 기존 허용 경로·검증·독립 검수·민감 작업 승인 절차를 통과해야 합니다. 다른 프로젝트의 안건은 섞지 않습니다.

**보고서 보기**에서 직원 발언과 검토 결과를 읽고 복사할 수 있습니다. **작업 정지**는 회의의 후속 호출도 멈춥니다. 앱/서버가 종료되어 중단된 회의는 자동 재호출하지 않고 중단으로 표시합니다. 기존 미션의 재개 정책은 별도입니다.

## 데이터와 검증 범위

캐릭터·대표·배경·자동 회의 설정은 `data/team_settings.json`, 회의·안건·대표 결정은 `data/company_meetings.json`에 저장합니다. 재설치 시 기존 데이터 폴더를 보존합니다. 게임 프로젝트에 이 파일들을 만들지 않습니다. 회의는 최대 200건을 보관하며 한도에 도달하면 새 회의를 중지하고 안내합니다.

자동 검사에서 신규 시작·기존 팀 보존·정원·과장·업무 분담·미션별 팀 고정·회의 단계·중요도 분류·실패·중단·중복 접수·안건 일괄 처리·프로젝트 분리를 검증했습니다. 브라우저에서 캐릭터 생성·실제 화면 이동·배경 전환·28명 조직·모바일·보고서·실제 승인 API를 확인하고 QtWebEngine에서도 기존 작업 흐름을 확인했습니다.

검사에는 격리된 임시 프로젝트와 테스트용 AI 응답을 사용했습니다. 로그인된 실제 AI의 회의 품질, Windows 설치/EXE와 Unity 실제 실행은 이 Linux 환경에서 검증하지 못했습니다.
