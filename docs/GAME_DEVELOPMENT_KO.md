# Unity·Godot 게임 제작 안내

이 프로그램은 엔진 프로젝트의 코드·씬·설정을 계획하고 수정·검증하는 개발 감독관입니다.
게임 플레이와 시각·소리 확인은 Unity/Godot 에디터에서 진행합니다.
전용 앱의 그래픽 안정 모드는 감독관 화면에만 적용되며 게임의 렌더러 설정은 바꾸지 않습니다.

## 시작 순서

1. 사용할 엔진과 버전을 정하고 해당 에디터에서 새 프로젝트를 만듭니다.
2. 감독관의 미션 센터에서 그 프로젝트 루트를 선택합니다. Godot은 `project.godot`, Unity는 `Assets`와 `ProjectSettings`가 있는 폴더입니다.
3. 전용 앱의 **앱 → 게임 프로젝트 검증 설정…**에서 프로젝트 폴더와 엔진 실행 파일을 지정하고 저장합니다.
   Godot은 Godot 실행 파일, Unity는 Hub 대신 해당 버전 Editor의 `Unity.exe`를 선택합니다.
4. 엔진 동작 테스트를 준비합니다. 아래 Godot/Unity 안내를 따릅니다.
5. 개발 방식을 **게임 개발**로 고르고 작은 플레이 루프 하나를 요청합니다.
6. 검증·독립 검수와 원본 반영 상태를 확인한 뒤 에디터에서 실제 플레이를 확인합니다.

설정은 감독관 설치 폴더 `data/engine-projects.json`에 프로젝트별로 저장합니다.
게임 프로젝트의 파일로 테스트 명령을 바꾸지 않습니다. 다른 프로젝트와 전체 Python 검증 기본값은 유지합니다.
다음 미션 및 결과 반영 후 재검증에 적용되므로 실행 중인 작업을 먼저 완료하거나 중지하세요.
Unity/Godot 자체와 라이선스·내보내기 템플릿은 별도로 설치해야 합니다.

## 처음 요청할 작업 예시

> Godot 4의 2D 프로젝트입니다. 키보드로 캐릭터를 이동하고 코인 3개를 모으면 승리하는 작은 플레이 루프를 만들어 주세요.
> 이동은 프레임 속도에 영향을 받지 않게 하고, 승리 후 다시 시작하면 위치·점수·상태가 초기화돼야 합니다.
> 이동·충돌·점수·승리·재시작에 실제 동작 테스트를 추가하고 씬과 리소스 연결도 확인해 주세요.
> 테스트 러너는 tests/director_tests.gd이며 실제 테스트 수를 DIRECTOR_TESTS JSON 한 줄로 출력하고 실패 시 종료 코드 1을 반환해야 합니다.
> 초기 범위는 scripts/, scenes/, tests/입니다. 외부 계정·결제·온라인 기능은 다음 단계로 미룹니다.

Unity라면 엔진/버전을 바꾸고 프로젝트 안의 `Assets` 하위 코드·씬과 EditMode/PlayMode 테스트 범위를 지정합니다.
처음에는 이동·충돌·승패·재시작에 집중하고 저장, 인벤토리, 스테이지 추가는 다음 미션으로 나누는 편이 검수하기 좋습니다.

## Godot 테스트

엔진 테스트 어댑터는 다음을 실제로 실행합니다.

1. `Godot --headless --path <격리 프로젝트> --editor --import`로 리소스를 가져옵니다.
2. `Godot --headless --path <격리 프로젝트> --script res://tests/director_tests.gd`로 프로젝트 테스트를 실행합니다.

`tests/director_tests.gd`는 `SceneTree`를 상속하는 테스트 진입점으로 준비합니다.
테스트에서는 프로젝트의 실제 게임 로직과 씬을 로드해 조건을 확인하고, 마지막에 아래 형식으로 출력합니다.

```gdscript
# passed/failed에는 실제로 실행한 assertion 결과를 집계합니다.
print("DIRECTOR_TESTS " + JSON.stringify({
    "passed": passed,
    "failed": failed,
    "total": passed + failed
}))
quit(1 if failed > 0 else 0)
```

요약이 없거나 중복되거나 테스트 0개이면 실패입니다.
실행 종료 코드, `ERROR:`/`SCRIPT ERROR:`와 테스트 수를 함께 확인하므로 에디터 시작만으로 통과하지 않습니다.
빌더에게 처음 작업을 요청할 때 진입점과 실제 게임 동작 테스트를 함께 준비하도록 완료 조건에 넣으세요.
기본 Python 테스트를 엔진 검증으로 간주하지 않습니다.
어댑터를 직접 점검하려면 프로젝트 폴더에서 다음처럼 실행합니다(아래 경로는 자신의 설치 위치로 바꿉니다).

```text
C:\감독관설치폴더\.venv\Scripts\python.exe C:\감독관설치폴더\scripts\run_engine_tests.py --engine godot --executable C:\도구\Godot_console.exe
```

Godot 4.6.3에서 실제 씬·SVG 리소스 가져오기, 이동 계산과 프레임 속도 독립성,
격리 수정, 테스트 증가, 원본 반영 후 재검증을 확인했습니다.
프로젝트가 GDExtension이나 C#을 사용한다면 해당 엔진 빌드와 언어 도구도 별도로 준비해야 합니다.

## Unity 테스트

Unity Test Framework를 준비하고, 실제 게임 로직을 검사하는 EditMode 또는 PlayMode 테스트를 작성합니다.
앱의 엔진 설정에서 테스트 모드를 고를 수 있습니다.
어댑터는 `-batchmode -nographics -projectPath ... -runTests -testPlatform ... -testResults ...`를 실행합니다.
매 실행마다 새 임시 XML 보고서를 사용하고 실제 `test-case` 결과를 집계합니다.
보고서 누락·손상, 테스트 0개, 전부 건너뛴 결과, 엔진 실행 오류는 통과하지 않습니다.
Unity 라이선스 활성화와 해당 Editor 버전 설치는 필요합니다.

현재 Linux 검수 환경에는 Unity가 없어 실제 Unity 실행은 검증하지 못했습니다.
NUnit 보고서의 정상·실패·빈 결과·위험한 XML 처리와 명령 구성을 확인했습니다.
같은 프로젝트를 에디터와 검증 작업에서 동시에 열지 않도록 하고, 빌드 타깃별 플레이·그래픽·오디오·패키징은 별도로 확인하세요.

## 씬·에셋 보존

새로 생긴 `.gd`, `.tscn`, `.tres`, `.uid`, `.unity`, `.prefab`, `.meta`, `.asmdef`, 셰이더·모델·오디오 등 주요 게임 파일을 다음 단계의 스냅샷에 전달합니다.
Unity `.meta` GUID와 Godot UID/리소스 경로를 임의로 재생성하지 않도록 게임 개발 지침에 명시했습니다.
게임 속 토큰처럼 `token_pickup.gd`라는 소스 이름도 보존합니다.
자격증명 파일과 엔진 캐시는 제외합니다.

새 미추적 파일은 1개 16MiB, 합계 128MiB까지 스냅샷에 포함합니다.
지원 형식의 큰 새 에셋이 상한을 넘으면 조용히 누락하지 않고 `SNAPSHOT_ASSET_LIMIT`으로 중단합니다.
큰 에셋은 Git에 먼저 커밋하고 필요한 LFS 도구를 준비하세요. 모든 엔진/독자 형식의 지원을 보장하지는 않습니다.
프로젝트 `.gitignore`에는 Godot `.godot/`, Unity `Library/`, `Temp/`, `Obj/`, `Logs/`, 빌드 산출물을 제외하세요.
소스와 씬·리소스의 원본은 유지해야 합니다.

완성 판정은 엔진 테스트와 독립 검수 증거를 기준으로 합니다.
실제 조작감, 아트·음악 품질, 기기별 성능, 최종 내보내기 결과는 별도 플레이 검수 항목입니다.
