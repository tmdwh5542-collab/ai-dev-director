# 미션 센터 개선판 검증 기록

검증일: 2026-11-13 (한국 시간). 기준 원본: `d2541ad`, v3.1.8.
Linux, Python 3.12.14, Chromium, Playwright 1.62.1에서 확인했습니다.

## 변경 영역별 검증

- 미션 조회 API·화면·기존 채팅 관련 Python 테스트: **32개 통과**.
- Python 캐시 회귀·HEAD 자율 수정·제안 빌더 관련 테스트: **74개 통과**.
- JavaScript 구문 검사, Python 컴파일, `git diff --check`: 통과.
- 실제 HTTP 서버와 임시 DB를 사용하는 Playwright 검증: 통과.

브라우저에서는 다음을 확인했습니다.

- 한글 목표 검색, 프로젝트·ID 검색 API, 상태 필터, 페이지 이동.
- 상세 테스트/검수 근거, 원본 적용 상태, Markdown 보고서 다운로드.
- 미션 텍스트의 HTML 삽입 방지.
- 준비 양식의 새로고침 복원과 스테이지 입력창으로의 초안 전달.
- 서버 바쁨, 통신 실패, JSON 응답 오류 시 입력 보존.
- 통신 실패/JSON 오류 후 재시도 요청 ID 유지.
- 요청 전송 중 다음 초안을 작성해도 이전 성공 응답이 새 초안을 지우지 않음.
- 폭 360, 390, 768, 800, 1024, 1280px 화면에서 페이지 전체의 가로 넘침 없음.
- 1440px 데스크톱 화면 캡처.
- 브라우저 저장소 차단 시 안내와 수동 복사가 가능한 입력 유지.
- 기록이 없는 초기 화면과 조회 장애의 구분.

## Python 바이트코드 오류 재현

1. `feature.py`에 `VALUE = 1`을 쓰고, 타임스탬프를 고정해 `.pyc`를 생성합니다.
2. 소스를 같은 크기인 `VALUE = 2`로 고친 뒤 같은 타임스탬프를 유지합니다.
3. 원본 검증기에서 `assert feature.VALUE == 1`은 **통과**, `== 2`는 **실패**했습니다.
4. 수정본에서는 `== 1`이 **실패**, `== 2`가 **통과**합니다.

각 명령에 새로운 `PYTHONPYCACHEPREFIX`를 제공해 복사된 작업본의 오래된 캐시를 읽지 않도록 했습니다.
기존 캐시 파일을 삭제하거나 소스를 수정하지 않는 것도 회귀 테스트에서 확인했습니다.
Python이 환경 변수를 무시하도록 사용자가 명령에 `-E`/`-I`를 명시하면 이 환경 변수 기반 격리도 무시됩니다.

확인한 항목:

- 선택한 절차가 최초 구현과 HEAD의 다음 마일스톤에도 한 번씩 유지됨.

- 과거 기록은 구조화된 참고 자료로 전달하고 기록 사용을 끄면 전달하지 않음.
- 폴더·파일·항목 상한을 지키고 가상환경/의존성/민감 폴더와 외부 링크를 탐색하지 않음.
- 2차 접수 기록의 중복 방지 호환성, 새 선택 사항 변경 시 내용 충돌 거부.
- 스테이지 초안 태그가 실제 HEAD 요청과 미션 예산·기억 옵션에 반영됨.
- 라이브러리 선택만으로 작업이 시작되지 않음.
- 방식/기록 옵션의 새로고침 복원, 시작 접수와 상세 보고서의 선택 유지.
- Claude/Codex 검수기의 실제 CLI 입력 프롬프트에 선택된 검수 지침이 포함됨 (프로세스 실행은 대역).

글로벌 ECC 플러그인 설치, 실제 구독 CLI의 종단간 실행, 실제 Windows PC 실행은 수행하지 않았습니다.
개발 방식 체크리스트는 계획 지침이며 검증 통과 증명으로 표시하지 않습니다.

## Windows 바탕화면 설치 패키지

설치·런처와 기존 HTTP/화면 관련 테스트 25개가 통과했습니다.
ZIP 추출 후 해시 목록 확인, 한글·공백 경로 설치 복사, 실제 companion 서버 시작과 미션 센터 응답,
반복 실행 시 같은 서버 재사용을 별도로 확인했습니다. 테스트 서버는 확인 후 종료했습니다.
Windows의 COM 바로가기 생성과 실제 Windows 앱 창 실행은 Linux 환경에서 직접 실행하지 못했습니다.
사용 절차와 전제 조건은 [Windows 설치 안내](DESKTOP_INSTALL.md)를 참고하세요.

## 전용 데스크톱 앱 추가

이전 Edge/Chrome 앱 창 방식은 Qt 전용 창으로 교체했습니다.
Windows 설치 과정에서 GUI 셸 EXE를 만들고 바탕화면 바로가기를 해당 EXE에 연결합니다.
백엔드는 전용 가상환경을 유지하므로 실제 검증 작업의 Python 실행 경로를 보존합니다.

- 전용 창, 실제 임시 미션 서버의 13개 미션 데이터 연결, Qt 파일 저장 대화상자를 통한 보고서 다운로드 검증 통과.
- 관련 런처/설치/탐색 경계/바로가기 인자 테스트 19개 통과.
- Qt 페이지를 프로필보다 먼저 정리하도록 수정 후 종료 코드 0 확인.
- Linux 헤드리스 환경에서 화면 픽셀 렌더링과 Windows의 실제 EXE/COM 바로가기 실행은 확인하지 못함.
- 배포 ZIP은 Windows에서 최초 설치 중 EXE를 생성하는 소스 기반 설치판이며, 빌드된 Windows EXE가 미리 포함된 파일은 아님.

## 내부 화면 깜박임 대응 (native fix1)

사용자의 Windows에서 보고된 깜박임의 단일 원인으로 확정하지는 않았습니다.
