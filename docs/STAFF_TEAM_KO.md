# 프로그램 안에서 직원과 역할 편집

회사 사무실 위의 **직원 채용·편집**을 누르면 팀을 수정할 수 있습니다.
새 회사는 대표 캐릭터 한 명부터 시작합니다. 아래 6명 구성은 선택해서 불러오는 초안입니다. 최신 캐릭터·부서·회의 기능은 [회사 운영 안내](COMPANY_SIMULATION_KO.md)를 참고하세요.

| 직원 | 업무 영역 | 기본 직무 |
| --- | --- | --- |
| 게임 기획자 | 기획·지휘 | 요구사항, 완료 조건, 직무별 단계 계획 |
| 게임 로직 개발자 | 구현 | 이동·입력·충돌·점수·승패·저장 |
| UI 개발자 | 구현 | 메뉴·HUD·인벤토리·화면 전환·접근성 |
| 레벨 디자이너 | 구현 | 씬·맵·스테이지·배치·리소스 연결 |
| 테스트 엔지니어 | 구현·테스트 작성 | 동작 테스트, 재현 조건, 경계 상황 |
| 품질 검수자 | 독립 검수 | 구현·테스트 증거와 결함·미검증 범위 확인 |

대표인 사용자와 프로그램의 테스트 서버는 이 직원 수와 별도로 표시합니다.
테스트 엔지니어는 AI가 테스트 코드를 작성하는 직무이고, 테스트 서버는 실제 검증 명령을 실행하는 감독관입니다.

## 수정하기

1. **직원 채용·편집**을 엽니다.
2. 이름, 전문 분야, 업무 영역, 담당 직무를 수정합니다.
3. **직원 추가**로 새 직원을 만들거나 **삭제**로 정리합니다. 부서당 과장 포함 최대 4명, 7개 부서 전체 28명까지 구성할 수 있습니다.
4. **팀 설정 저장**을 누릅니다. 다음 새 미션부터 적용됩니다.

직원 이름은 24자, 직무 설명은 400자까지입니다.
기획·지휘, 구현, 독립 검수 담당은 각각 한 명 이상 필요합니다.
기획은 기획과 과장인 기획 담당을 우선합니다. 검수는 미션에 명시된 검수 담당을 따르며, 명시가 없으면 배정 횟수가 적은 검수 직원을 선택합니다.
구현 영역의 여러 직원은 전문 분야와 HEAD의 단계별 배정에 따라 작업합니다.
**게임 개발팀 6명 불러오기**는 편집 중인 양식을 기본 구성으로 바꾸며, 저장해야 반영됩니다.

저장 중에는 입력을 잠시 잠가 입력한 변경이 저장 응답 뒤 사라지지 않게 합니다.
닫기/ESC 시 미저장 변경을 확인합니다.
다른 창에서 설정을 먼저 저장한 경우 덮어쓰지 않고 충돌을 안내하며, 편집 중인 내용은 남깁니다.
필요하면 **서버 설정 다시 불러오기**로 최신 구성을 가져오세요.

## 실제 작업에 반영되는 내용

직원은 기존 AI 연결을 공유하는 전문 직무입니다.
한 미션은 기존 기획 → 구현 → 검증 → 독립 검수 → 판단 순서로 진행합니다.
직원 수에 맞춰 불필요한 호출을 만들지 않도록 계획 지침에 명시했습니다.

- HEAD에 현재 팀과 담당 직무를 전달해 작업을 작은 단계로 나누도록 합니다.
- 구현 단계의 `assigned_staff_id`는 해당 미션 팀의 구현 직원 중에서 선택합니다.
  지정을 못했거나 역할이 맞지 않으면 목표와 경로를 참고해 적합한 직원을 선택합니다.
- 실제 구현/검수 프롬프트에 배정된 직원과 직무 지침을 전달합니다.
- 기존 경로·파일 수·diff 상한·엔진 검증·독립 검수 정책은 유지됩니다.
- 실제 CLI 호출에 직원 ID·당시 이름·팀 구성 해시를 기록합니다.
- 사무실은 ID와 팀 구성, 실행 역할이 일치하는 실제 호출만 해당 직원의 업무로 표시합니다.

미션을 시작할 때 팀 구성을 복사해 보관합니다.
도중에 직원 이름·직무·인원을 바꿔도 진행/재개/재계획은 해당 미션의 팀을 유지합니다.
사무실에는 진행 미션의 팀을 표시하고 다음 팀의 인원도 안내합니다.
기록 상세와 Markdown 보고서에서 미션 당시 팀, 구현 담당자, 호출 당시 이름을 확인할 수 있습니다.
예전 기록에 직원 ID가 없으면 현재 직원 이름으로 소급해서 표시하지 않습니다.

## 저장과 업데이트

팀 설정은 감독관의 데이터 폴더 `team_settings.json`에 저장합니다.
Windows 기본 설치에서는 `%LOCALAPPDATA%\AI Dev Director\mission-center-v3\data\team_settings.json`입니다.
재설치 시 다른 설정과 함께 보존합니다. 게임 프로젝트 폴더에는 저장하지 않습니다.
작업 기록 DB는 직원 관련 열만 추가하며 기존 호출 행을 보존합니다.

## 검증 범위

직원 수/역할/입력 상한, 저장 충돌, 로컬 출처·토큰 검사, 직무 선택과 권한 보존,
기존 DB 형식의 데이터 보존, 미션 팀 고정과 재계획, 실제 구현/검수 프롬프트와 호출 문맥 전달을 자동 검증했습니다.
브라우저에서는 이름·직무·직원 추가/삭제·재접속 보존·기본팀 복원·부서 정원·모바일 선택·편집 충돌과 초안 보존을 확인했습니다.
실제 QtWebEngine에서도 직원 편집 창에서 이름을 저장하고 회사 화면에 반영되는 것을 확인했습니다.

Windows에서의 실제 EXE 실행과 로그인된 AI CLI의 추론 결과는 이 Linux 환경에서 직접 검증하지 못했습니다.
프롬프트 전달 및 기록 검증에는 테스트용 CLI 응답을 사용했습니다.
실제 역할 배분 결과는 미션별 기록을 확인하세요.
