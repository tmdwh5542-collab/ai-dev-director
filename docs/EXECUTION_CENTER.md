# 미션 센터 2차 개선: 작업을 시작하고 복구하는 흐름

첫 개선판의 조회·초안 기능에 이어, 센터 안에서 프로젝트 선택부터 작업 시작·실패 원인 확인·수정 지시까지 이어지도록 개선했습니다.
기준은 공개 저장소 `d2541ad`와 이 작업에서 만든 첫 개선판입니다. 사용자 PC의 trial 설치본은 별도로 검증하지 않았습니다.

## 프로젝트와 작업 규모

**프로젝트 선택**에서 최근 사용한 저장소를 고르거나, 폴더 찾아보기, 경로 직접 입력을 사용할 수 있습니다.
최근 목록 조회는 폴더를 만들거나 Git을 초기화하지 않습니다. 사용자가 경로를 선택·저장하면 기존 프로젝트 준비 정책을 사용합니다.
폴더 선택 창이 열리지 않아도 경로 직접 입력은 계속 사용할 수 있습니다.

새 미션에서 목표·완료 조건·주의사항과 **빠르게 / 표준 / 깊게** 규모를 선택합니다.
규모는 기존 설정의 실행 예산을 고르는 기능입니다. 권한 심사나 검증을 약화하지 않습니다.
선택 당시의 절대 프로젝트 경로와 규모가 시작 요청에 함께 저장됩니다. 다른 탭이 채팅 프로젝트를 바꾸어도 접수한 미션의 대상은 바뀌지 않습니다.

**미션 시작**은 실제 CLI 작업을 요청하는 버튼입니다. 결과 반영은 기존 `config.yaml`의 `auto_apply` 설정을 따릅니다.
**스테이지에서 확인**은 실제 시작 없이 초안만 기존 입력창에 넘깁니다.

## 시작 요청과 중복 방지

`data/director.db`의 `mission_launches` 테이블에 요청 ID, 정규화된 목표·프로젝트·규모, 상태와 결과를 보관합니다.
클라이언트는 즉시 접수 응답을 받고, HEAD 계획은 별도 스레드에서 처리합니다.
같은 서버의 기존 채팅 HEAD 슬롯도 공유하므로 동시에 다른 HEAD 요청을 시작하지 않습니다.
미션 자체는 기존 실행기와 프로젝트별 실행 슬롯을 사용합니다.

- 같은 요청 ID와 같은 내용: 저장된 접수/결과를 반환하며 다시 실행하지 않습니다.
- 같은 ID로 다른 목표·프로젝트·규모 제출: 충돌로 거부합니다.
- 새로고침: 브라우저에 보관한 ID로 서버 상태를 읽습니다. 자동 재제출하지 않습니다.
- 시작 응답 유실: **접수 확인**으로 저장된 결과를 찾거나 **같은 요청 재전송**을 사용할 수 있습니다.
- 서버 종료/재시작 중이던 요청: 프로세스 ID와 생성 시각으로 중단을 감지해 `interrupted`로 표시합니다. 자동으로 다시 실행하지 않습니다.
- 중단 시점에 실제 미션이 이미 생성되었을 수 있으므로 미션 기록을 먼저 확인해야 합니다.
- HEAD의 추가 질문, 권한 확인, 거절은 각각 다른 상태로 표시합니다. 단순 접수를 미션 시작으로 표시하지 않습니다.

요청 기록은 로컬 DB, 현재 보고 있는 요청 ID는 해당 브라우저의 로컬 저장소에 있습니다.
다른 브라우저·포트는 같은 브라우저 초안을 공유하지 않습니다. 브라우저 저장소를 삭제하면 현재 요청 배너 복원이 안 되지만 생성된 미션 기록은 서버에 남습니다.
시작 요청 기록을 삭제한 새 DB로 바꾸면 이전 요청 ID의 중복 방지 기록도 없어집니다.

## 실패 근거와 수정

각 단계에서 다음을 선택적으로 펼쳐 볼 수 있습니다.

- 실제 빌드·테스트·린트 명령, 성공 여부, 종료 코드, 출력.
- 검수 요약과 P0/P1/P2 지적.
- 검증 시 기록된 코드 변경 내용.

서버에 저장된 미션·단계에서 실행 ID를 찾습니다. 브라우저가 임의 파일 경로나 실행 ID를 지정해 읽는 방식은 허용하지 않습니다.
증거 파일은 실행 기록 폴더 안에서만 읽고 외부를 가리키는 심볼릭 링크는 거부합니다.
JSON 근거 파일당 512 KiB, 명령당 출력 마지막 12,000자, 변경 내용 앞부분 16,000자 등 표시 상한이 있습니다.
아직 근거가 없거나 오래된 기록 파일이 없으면 그대로 안내하며, 없는 테스트 통과나 검수 결과를 만들어 표시하지 않습니다.
로그는 텍스트로 표시합니다. HTML처럼 생긴 출력도 실행하지 않습니다.

실패·예산 소진·정지된 미션은 **이어서 진행 · 2단계 추가**를 사용할 수 있습니다.
추가 수정 지시를 300자 이내로 적고 **수정 지시로 재계획**을 누를 수도 있습니다.
예산을 이미 쓴 경우에는 재계획이 즉시 예산 소진으로 끝나지 않도록 추가 단계를 확보합니다.
프로세스가 사라진 `RUNNING` 미션은 **중단된 미션 재개**로 이어갈 수 있습니다.
완료된 미션은 새 미션으로 후속 작업을 요청합니다. 완료된 기록에 실행되지 않는 재개 스레드를 만드는 기존 동작은 거부하도록 바꿨습니다.

재계획은 중단된 실행의 권한을 승인하는 동작이 아닙니다. 기존 HEAD 심사와 Scope Guard를 그대로 거칩니다.
진행 중인 미션에는 재개·적용 제어를 표시하지 않으며 서버에서도 실행 중 적용을 거부합니다.
결과 적용은 항상 충돌 보류 정책을 사용합니다. 센터에서 충돌 파일 건너뛰기를 요청하지 않습니다.

## API

| 주소 | 용도 |
| --- | --- |
| `GET /ops/projects` | 현재/최근의 접근 가능한 프로젝트 |
| `POST /ops/mission-launch` | 대상과 규모를 고정한 비동기 미션 시작 요청 |
| `GET /ops/mission-launch?request_id=...` | 저장된 접수 상태와 결과 |
| `GET /ops/mission-step?mission_id=...&index=...` | 선택한 단계의 제한된 실행 근거 |
| `POST /ops/mission-control` | 적용·재개·연장·수정 지시 재계획 |

새 변경 API는 로컬 출처 검사와 `X-Solomon-Bridge` 토큰을 요구합니다.
종량제 API를 추가하지 않았습니다. 실제 개발 실행에는 원래 프로그램이 지원하는 로그인된 구독 CLI가 필요합니다.

## 검증

`tests/test_mission_execution_center.py`는 동시 중복 접수, 내용 충돌, 중단 감지, HEAD 슬롯,
토큰/출처 검사, 실행 로그 상한, 외부 링크 차단, 실제 재개 예산·수정 지시, 실행 중 적용 거부,
프로젝트 목록의 읽기 전용 동작과 스레드 시작 실패 복구를 확인합니다.

`tests/browser/execution_center.cjs`는 임시 저장소와 임시 DB에서 실제 HTTP API로 프로젝트를 선택하고
미션 시작·새로고침·응답 유실 복구·질문/거절 표시·실패 근거·재계획·재개·충돌 안내·모바일 버튼 접근을 확인합니다.
AI 계획과 실제 미션 실행만 테스트 대역으로 바꿉니다. 실제 구독 CLI나 사용자 프로젝트를 실행하지 않습니다.

첫 개선판의 브라우저 회귀 테스트도 유지합니다. 전체 결과와 남은 원본 실패는 [검증 기록](VALIDATION_MISSION_CENTER.md)에 기록합니다.

## 함께 보완한 호환성

호출 기록의 공급자 판별은 Windows와 POSIX 경로를 모두 인식합니다. Linux에서 Windows 형식의 CLI 경로를 다룰 때 호출과 토큰이 빠지던 문제를 수정했습니다.
Builder의 참고 문서 입력은 POSIX 절대 경로도 인식합니다. 공백이 있는 경로는 따옴표로 감싸거나 명시적인 `reference_paths`에 넣습니다.
URL 전체를 먼저 제외하므로 IPv6 주소, 호스트 끝의 점, URL 쿼리 안의 `/path.md`를 로컬 참고 문서로 읽지 않습니다.
없어진 명시적 참고 파일은 기존처럼 오류로 표시합니다. 문서 읽기 크기와 문맥 예산 제한은 유지합니다.
