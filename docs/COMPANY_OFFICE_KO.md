# 입체 회사 사무실 화면

전용 앱의 기본 시작 화면을 **회사 사무실**(`/office`)로 연결했습니다.
위에서 비스듬히 내려다보는 2.5D 사무실이며 SVG와 CSS로 표시합니다.
게임 엔진이나 WebGL을 추가로 설치하지 않아도 감독관의 전용 화면에서 볼 수 있습니다.

| 자리 | 역할 | 표시 근거 |
| --- | --- | --- |
| 대표실 | 사용자 | 목표와 완료 조건 결정 |
| 기획실 · 개발 이사 | HEAD | 계획·채팅·다음 단계·결과 판단의 실제 AI 호출 |
| 개발실 · 개발 담당 | BUILDER | 코드·씬·리소스 구현의 실제 AI 호출 |
| 테스트실 · 운영 감독 | Director | 현재 미션과 실행 ID가 일치하는 VERIFYING 단계 |
| 품질실 · 검수 담당 | REVIEWER | 독립 검수의 실제 AI 호출 |

기존 실행 절차를 회사의 직무와 부서로 표현합니다.
최신판은 대표 캐릭터를 먼저 생성하고 **직원 채용·편집**에서 직접 직원을 생성합니다. 부서당 과장 포함 최대 4명, 전체 28명입니다. [캐릭터 회사·회의 운영](COMPANY_SIMULATION_KO.md)을 참고하세요.
직무가 실제 작업 지침·미션 기록·호출 기록에도 연결됩니다. [직원 편집 안내](STAFF_TEAM_KO.md)를 참고하세요.

## 사용 방법

- **직원 채용·편집**에서 이름·전문 분야·업무 영역·담당 직무를 수정하고 다음 미션부터 적용합니다.
- 각 자리나 이름표 또는 화면 아래 직원 선택 버튼을 누르면 오른쪽에 부서의 역할, 담당 AI, 현재 업무를 표시합니다.
  키보드 Tab 및 Enter/Space로도 선택할 수 있습니다.
- 호출 중인 담당 AI가 다음 작업의 설정과 다를 경우 현재 실제 호출의 AI를 우선 표시합니다. 직원 ID·역할·팀 구성이 일치하는 호출을 연결합니다.
- 실제 AI 호출이 진행 중일 때 해당 부서의 표시와 업무 경로가 움직입니다.
  네트워크 연결이 끊기면 업무 중 표시를 멈추고 마지막 수신 기록임을 안내합니다.
- 서버 검증 단계는 테스트 성공과 구분합니다. 실제 테스트·리뷰·적용 결과는 미션 센터의 기록에서 확인합니다.
- 오늘 호출 수·CLI 작업 시간·토큰과 최근 호출 기록을 볼 수 있습니다.
  CLI 작업 시간은 호출 시간 합계이며 벽시계상 경과 시간과 다를 수 있습니다.
  추정 토큰에는 `~`, 집계되지 않은 토큰에는 `미기록`을 표시합니다.
- 사무실 아래 목표 입력란에서 **업무 지시서 준비**를 누르면 미션 센터의 초안으로 전달합니다.
  프로젝트와 완료 조건을 검토하고 **미션 시작**을 눌러야 실행됩니다.
  기존 목표를 바꾸려 할 때는 확인하며, 저장소 사용이 안 되면 내용을 복사할 수 있게 안내합니다.
- 미션 센터·라이브 스테이지·기존 작업실로 이동할 수 있습니다.
- 재설치할 때는 화면 위의 **시스템 중지**를 누른 후 앱 창도 닫고 설치 파일을 실행하세요.
  **작업 정지**는 미션을 멈추며 서버 화면은 계속 켜둡니다.

## 연결과 권한

읽기에는 기존 `/ops/activity`, `/status`, `/ops/roles`를 사용합니다.
작업 정지·시스템 중지는 기존 로컬 출처 검사와 토큰 검사를 그대로 사용하며, 사용자 확인 뒤 요청합니다.
권한과 미션의 실행·반영 절차를 바꾸지 않습니다. 화면 문자열은 API/사용자 내용을 HTML로 해석하지 않습니다.

## 검증

- 관련 Python/HTTP/런처/네이티브/미션 센터 테스트 **41개 통과**.
- 브라우저: 부서 선택, 실제 호출 담당자 우선 표시, 일치하는 검증 단계만 표시,
  오프라인·복구, 문자열 주입 거부, 모바일 레이아웃, 초안 전달 시 자동 실행하지 않음,
  토큰을 사용한 시스템 중지 성공/실패 처리 검증 통과.
- 기존 미션 센터와 실행 센터 브라우저 회귀 시나리오 통과.
- 실제 QtWebEngine에서 미션·보고서·작업실·프로젝트 선택에 이어 회사 화면 연결 검증 통과.
- Linux의 frozen GUI 셸 시작·내부 페이지 동작 검증 통과.
- 스크린샷은 검증용 프로젝트와 호출 데이터로 만든 예시입니다. 사용자 PC의 현재 작업을 찍은 것은 아닙니다.

Windows EXE 실행과 사용자 PC의 그래픽 환경은 이 Linux 환경에서 직접 검증하지 못했습니다.
게임 엔진 설정과 실제 개발 작업 방법은 [게임 제작 안내](GAME_DEVELOPMENT_KO.md)를 참고하세요.


최신 직원 편집판의 검증 결과와 기본 팀은 [직원 편집 안내](STAFF_TEAM_KO.md)에 정리했습니다.
